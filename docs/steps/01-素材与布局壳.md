# 步骤 1 — 素材与布局壳

> 返回：[步骤索引](./README.md)

---

## 目标

用切好的 PNG 在页面上拼出一台**静止**的像素 Gameboy，并标定屏幕可绘制区域，为后续 UI / iframe / 聚焦动画打好坐标基础。Demo 页提供静态合成预览。

---

## 前置条件

- [ ] **步骤 0 已由你确认验收通过**
- [ ] 切图已就绪（至少可用占位图；正式图见计划书 8 件套）。缺图时可用色块占位，但须在验收备注中标明
- [ ] 尽量提供：基准尺寸 + 各层坐标 + **绿屏内容区内缘**坐标

---

## 本步做什么

1. 将素材放入 `public/assets/gameboy/`（命名与计划书一致或文档注明映射）
2. 实现 `GameboyStage`（或等价）：按图层叠放
   - `body` → `screen` → 各按钮阴影与按钮（可先静态，无交互）
3. 使用 `image-rendering: pixelated`（或等价）避免模糊
4. 标定并在代码/配置中写出 **screen 内容区**矩形（相对 screen 或 stage）
5. 正式页：居中展示静止整机（可有简单页面背景色）
6. Demo 页：增加「合成预览」区块，展示同一套舞台组件
7. 若暂无正式切图：允许用 `bg_test.jpeg` 整图或色块占位，但必须留下 `TODO` 与坐标配置结构，便于换正式 PNG

---

## 本步明确不做

- 不做 D-Pad 倾斜、不做按钮按下态逻辑（贴图可摆上，但点击无业务行为）
- 不做 boot / menu / 列表 / NES.css 流程
- 不做 zoom、蒙版聚焦、iframe
- 不加载 `games.json` 驱动 UI（可读文件但不做菜单）
- 不做键盘映射
- 不做部署

## 验收清单

### A. 代理自验

- [ ] 正式页可见完整机身合成（或已声明的占位方案），无大面积错位
- [ ] 各图层层级正确：屏在机身之上，按钮在合理位置
- [ ] 缩放浏览器窗口时，舞台有合理缩放/居中策略（不至于直接裁切到不可辨）
- [ ] 像素缩放无明显发糊（相对 JPEG 放大应更干净；若仍用 jpeg 占位须注明）
- [ ] screen 内容区坐标已写入代码/配置，并可用临时描边/半透明块在开发模式核对（验收时可开可关）
- [ ] Demo 页「合成预览」可见
- [ ] 无按钮业务逻辑、无 zoom、无 iframe 游戏

### B. 你的手动验收

- [ ] 图层对齐符合你的切图预期（指出需微调的像素级问题也算本步返工）
- [ ] 屏幕内容区标定位置正确（后续 UI 将画在这里）
- [ ] 占位 vs 正式图状态你已知晓
- [ ] 确认：**可以开始步骤 2**
