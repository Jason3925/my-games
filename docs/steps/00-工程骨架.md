## 目标

搭好可本地运行的静态前端工程，建立约定目录与两个入口（正式站 / Demo 实验室），为后续贴图与组件预留位置。**本步结束时还没有可见的 Gameboy 成品，也没有真实交互。**

## 本步做什么

1. 使用 Vite 初始化前端工程（TypeScript；框架可选原生 TS 或极轻量结构，但需能跑 dev/build）
2. 建立目录约定（可按计划书微调，但需存在且用途明确）：
   - `public/games/`
   - `public/assets/gameboy/`（可先空，可放 README 占位说明）
   - `public/assets/covers/`
   - `public/games.json`（空列表或 1 条占位元数据）
   - `src/`（入口与后续组件目录占位，如 `src/components/`、`src/app/`、`src/demo/`）
   - `docs/`（已有文档保留）
3. 配置双入口：
   - 正式入口：`index.html` → 主应用壳（可为极简占位页）
   - Demo 入口：`demo.html` → 组件实验室壳（可为极简占位页，列出「即将测试的区块」标题即可）
4. 能执行 `npm install` / `npm run dev` / `npm run build`
5. 根目录补充简短 `README.md`：如何安装、启动、打开正式页与 Demo 页
6. `.gitignore` 覆盖 `node_modules`、`dist` 等

---

## 本步明确不做

- 不接入 Gameboy 切图，不做图层合成
- 不实现 D-Pad / 按钮 / Tilt
- 不引入 NES.css 到业务流程（允许 `package.json` 先不装）
- 不实现 boot / menu / zoom / iframe
- 不放入任何 Godot 导出文件
- 不做部署、不做 CI
- 不改写 [步骤文案.md](../步骤文案.md) 里的玩家文案（本步无屏幕流程）
