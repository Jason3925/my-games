# my-games 落地计划书

> 像素掌机外壳 + Godot HTML 小游戏展柜。朋友打开网站即可「开机 → 选游戏 → 放大游玩 → 返回」。

---

## 1. 产品目标

| 目标 | 说明 |
|------|------|
| 核心体验 | 网站本身像一台可交互的像素 Gameboy |
| 内容载体 | Godot 导出的 HTML5 小游戏，经 iframe 加载 |
| 视觉语言 | 机身用自有像素素材；屏幕内 UI 用 [NES.css](https://github.com/nostalgic-css/NES.css) |
| 受众 | 分享给朋友即开即玩，桌面优先，兼顾移动端 |

**不做（首期）：** 插卡带动画、账号系统、服务端、复杂路由。

---

## 2. 体验流程（状态机）

```
boot ──► menu ──► zooming/loading ──► playing ──► zoom-out ──► menu
                      ▲                                         │
                      └─────────────（可再次选择）─────────────────┘
```

| 状态 | 玩家看到什么 | 可操作 |
|------|--------------|--------|
| `boot` | 全景机身；屏幕内启动动画 / 进度条 | 等待（可跳过） |
| `menu` | 全景机身；屏幕内游戏列表 + 右侧 mini 图 | 方向键选游戏；A / Start 确认 |
| `zooming` | 机身放大，屏幕成为焦点；外围变暗 | 锁定输入 |
| `loading` | 屏幕内加载进度（可与 zoom 重叠） | 锁定输入 |
| `playing` | 屏幕区 iframe 跑游戏；外围弱化 | 游玩；B / Esc / 约定手势返回 |
| `zoom-out` | 收回全景；卸载 iframe | 锁定输入 |

## 3. 素材分层方案

所有资源建议 **PNG + 像素对齐**，目录约定：`assets/gameboy/`。

| 编号 | 文件（建议名） | 内容 | 用途 |
|------|----------------|------|------|
| 1 | `body.png` | 机身底板，**无屏幕、无按钮** | 常驻背景层 |
| 2 | `screen.png` | 独立显示屏（含边框 / 绿屏底） | 屏幕层；聚焦时突出，外围变暗 |
| 3a | `dpad.png` | 方向键本体 | 3D Hover Tilt |
| 3b | `dpad-shadow.png` | 方向键阴影 | 随倾斜偏移，增强体积感 |
| 4a | `btn-action.png` | A/B 共用按钮贴图 | 按下缩放 / 下沉 |
| 4b | `btn-action-shadow.png` | A/B 共用阴影 | 按下时阴影收拢或变淡 |
| 5a | `btn-option.png` | Select/Start 共用贴图 | 按下反馈 |
| 5b | `btn-option-shadow.png` | Select/Start 阴影 | 同上 |

### 3.1 合成与布局

```
[页面背景色 / 桌面氛围]
  └─ GameboyStage（可整体缩放 / 位移）
       ├─ body.png
       ├─ screen.png + 屏幕内容层（NES UI / iframe）
       ├─ dpad-shadow → dpad（tilt）
       ├─ action-shadow ×2 → action ×2（A / B）
       └─ option-shadow ×2 → option ×2（Select / Start）
```

各部件用 **绝对定位 + 相对机身的百分比或设计稿像素坐标** 对齐。切图时请同步给出一份坐标表（见 §7）。

### 3.2 聚焦与变暗策略

开始游戏后要「屏幕突出、其余变暗」，推荐：

1. **整机 `GameboyStage` 做 transform 放大**，使 `screen` 区域落到视口舒适区  
2. **屏幕以外**加半透明黑色蒙版（`pointer-events: none`），或给 `body` + 按钮层降 `brightness` / 加暗色 overlay  
3. **`screen` 层提高层级**，不被蒙版盖住（蒙版挖洞或 screen 叠在蒙版之上）

首期用 CSS 蒙版即可，不必改素材。

### 3.3 交互与素材的对应

| 控件 | 视觉技术 | 逻辑 |
|------|----------|------|
| 方向键 | 3D Hover Tilt（按点击分区：上/下/左/右） | menu：上下切换列表；左右可留空或翻页 |
| A / B | 按下下沉 + 阴影变化 | A = 确认开始；B = 返回 / 取消 |
| Select / Start | 同上（一套图两处复用） | Start = 开始（可选与 A 同）；Select = 预留 |

键盘映射（桌面必备）：`↑↓` / `Enter·Z·Space` / `Esc·X`。

## 4. 屏幕内 UI（NES.css）

仅在 `screen` 内容层使用，不污染机身外表。

| 场景 | 组件意向 |
|------|----------|
| 启动 | 进度条 + 短文案 |
| 菜单 | 列表（当前项高亮）+ 右侧封面 mini 图 |
| 加载 | 进度条；尽量贴近 iframe 真实加载 |
| 错误 | 对话框（加载失败可重试 / 返回） |

字体：英文可用 Press Start 2P；**中文用像素字体（如 Zpix）**，全局设在屏幕容器内。

## 5. 游戏接入

```
public/games/
  <game-id>/
    index.html          # Godot Web 导出入口
    …                   # wasm / pck / js 等
assets/covers/
  <game-id>.png         # 列表右侧 mini 图
games.json              # 元数据清单
```

`games.json` 字段草案：

```json
{
  "games": [
    {
      "id": "demo-01",
      "title": "示例游戏",
      "cover": "/assets/covers/demo-01.png",
      "entry": "/games/demo-01/index.html",
      "description": "一句话介绍"
    }
  ]
}
```

外壳 ↔ 游戏：`postMessage`（如 `my-games:ready` / `my-games:exit`）。返回时 **销毁 iframe**，再执行 zoom-out。

Godot 导出约定（首期）：统一分辨率倾向、画布居中、禁用多余浏览器 UI。

## 6. 技术架构（首期）

| 层级 | 选择 | 理由 |
|------|------|------|
| 工程 | Vite + 原生 TS（或轻量 React） | 静态部署简单；组件 demo 好拆 |
| 样式 | 自有 CSS + NES.css（仅屏幕内） | 机身与系统 UI 分离 |
| 宿主 | iframe | 隔离 Godot WASM |
| 部署 | Cloudflare Pages / GitHub Pages / Vercel | 纯静态 |

建议包结构：

```
my-games/
  docs/                 # 计划与文案
  public/
    games/              # Godot 导出
    assets/gameboy/     # 切图
    assets/covers/
  src/
    main.ts
    app/                # 主体验状态机
    components/         # DPadTilt / ActionButton / OptionButton / Screen...
    demo/               # 组件实验室页面
  index.html            # 正式入口
  demo.html             # 组件 demo 入口
```

## 8. Demo 页面（组件实验室）

路径：`/demo.html`（或 `/demo/`）。

**目的：** 不进完整状态机，单独验收交互与视觉。

| 区块 | 验收点 |
|------|--------|
| D-Pad Tilt | 点击/按住上、下、左、右时倾斜方向正确；松手回弹；阴影跟随 |
| A/B 按下 | 下沉、阴影变化、可连续点按 |
| Option 按下 | 同上 |
| Screen 聚焦预览 | 一键模拟「蒙版变暗 + 屏幕提亮/放大」 |
| NES.css 样例 | 进度条、列表、对话框在绿屏色上的观感 |
| 合成预览 | 用现有切图拼一台静态机（可先占位） |

Demo 页与正式页共用 `src/components/*`，避免两套实现。

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| JPEG 测试图边缘发糊 | 正式资源一律 PNG + `image-rendering: pixelated` |
| Tilt 在触控上难用 | 点击分区为主，hover 仅增强桌面 |
| Godot 包体大 | 按需加载；loading 接真实进度 |
| iframe 焦点丢失 | 进入 playing 时 `iframe.focus()`；返回时焦点回舞台 |
| 小屏机身过大 | 小视口可提高初始缩放或几乎全屏 screen |
| 多线程 Godot 需 COOP/COEP | 部署头配置；或首期单线程导出 |

## 11. 成功标准（首期可分享）

1. 打开网站有开机感，能进入游戏列表  
2. 方向键（及键盘）可选游戏，右侧显示 mini 图  
3. 确认后放大 + 加载，进入可玩状态  
4. 能返回全景菜单，再次选择  
5. Demo 页能单独演示 D-Pad Tilt 与其它按钮反馈
